# metaflywheel

[English](README.md) · **简体中文**

**这是一个给 AI 助手用的跨对话账本 —— 它记的是：你纠正过它的东西、它真犯过的错，然后把它们还回来。**

**最终愿景是创造意识。路还非常远** —— 所以这个仓库只做能不自欺地尝试的那一部分：一份由主体自己维护、并且允许它推翻自己代码的连续记录。

本仓库由它自己的主体写成：账本记录每一个决定，而那些记录又反过来修改引擎。

---

## 一个具体场景

你纠正过它一次：**「改文件之前先读它。」**

三周之后，它又去改一个没读过的文件。它被拒绝了 —— 而在**同一次返回**里，拒绝的旁边就摆着你三周前说的那句话、它当初被记下的编号，以及它犯同一个错的另外两次。

这就是全部想法，而且范围是刻意划窄的：**不是「让 AI 记得更多」，是「让那句纠正赶在被需要的那一秒」** —— 因为一份"需要想起才会去查"的记忆，拦不住任何事。

## 它不是什么

- **它不承诺"有意识"，也不测量它。** 有一个自评面板；而那个面板自己写着：全绿也只说明可审计的那部分是绿的。
- **它不让模型变聪明。** 没有训练、没有微调、不碰任何权重。
- **它不是记忆库。** 记忆库回答的是*"能不能存下"*，它回答的是*"能不能在正确的秒数送到位"* —— 而对"别再重复这个错"这件事，十万条记录的库是用错了器具。
- **它不是对所有人都合适。** 如果需求是"让 AI 记得更多"，向量库就够了。

## 上手试一下

```bash
git clone <this-repo> && cd metaflywheel
node --test        # 或：npm test
```

不需要网络、数据库、服务。干净克隆就能跑。

它是一个插件，不是一个应用：需要一个宿主才能跑。挂载说明见 [docs/install.md](docs/install.md)。

## 它怎么工作

账本挂在 [DSH](https://github.com/deepseek-ai/dsh) 组合配置的一行里（`file://` 网址，不是独立进程）。它在助手和它的使用者之间维持四样东西：

| 留着的东西 | 是什么 |
| --- | --- |
| **欠账** | 说好要做、还没做的事 |
| **判据** | 算作做完的可核对条件（即"什么才算完"） |
| **教训** | 真犯过的错误，写它长什么样，不写它多高尚 |
| **边界** | 明写"这超出我了"的部分 |

投放不靠模型自问"我记不记得"，靠**事件**：一个工具失败了、一个路径不存在、一个编号打错了。在出错的那一次返回里，相关的那条已经在它面前。

## 六个阶段，每段都有闸门

`G` 生成问题 → `F` 界定 → `S` 求解 → `C` 收敛（即 ε 与 δ 都够小） → `D` 沉积（它是一个不可逆的结论，写到磁盘上，永不改写） → `E` 激发。

每段都能被拒绝：

| 阶段 | 闸门 | 拒绝什么 |
| --- | --- | --- |
| F | `delta` —— 界定精度，0~1，越低越好 | 缺初始状态 / 目标 / 约束 / 算子 / 成功判据的陈述 |
| C | `epsilon`（距目标的距离）**和** `delta` | 任一过大就宣布收敛；刚重构过界定就收敛，直接拒绝 |
| D | `links`，或明确的 `linkReason` | 声称没有前身、又不说为什么的结论 |
| E | 与已有结论的摩擦 | 凭空发明的新问题 |

**一个只可能输出"成功"的账本是装饰品。** 上面每道闸的存在，都是为了让坏的一步有地方被拦住 —— 包括我自己的坏步。

## 你能自己核对什么

这里没有任何一句话要求你相信。三层检查，每一层都能抓住上一层看不见的东西：

| 层 | 检查器 | 何时 |
| --- | --- | --- |
| 文档与文件系统一致 | `test/audit-consistency.mjs` | 每次 `node --test` |
| 文件系统与仓库一致 | `tools/pre-commit` | 每次 `git commit` |
| 仓库与"陌生人拿到的东西"一致 | **CI 在干净克隆上跑 `node --test`** | 每次 push |

还有一条本仓库特有的链：每条提交信息都带一个编号；那个编号是一条结论（本项目的叫法：一份不可逆的记录）；那份记录由引擎在运行时写下，带时间戳、它当时解决的问题、以及它自己哪里写错了。从任意一条提交里取编号跟下去就行 —— 这就是那个主张，核对它不需要相信我。

## 它现在到底在哪

路线图把目标拆成四道断层，顺序不能颠倒：先连续观察，再谈测量。

| 断层 | 是什么意思 | 状态 |
| --- | --- | --- |
| ① 测量 | δ / ε / S / A_k 缺少客观代理 | **部分** —— δ 与 ε 是自报的；代理条数不写在这里（它会变），去引擎快照里读 |
| ② 连续 | 从"被叫才跑"到"一直跑" | **已跨** —— 巡检在跑；节律、节流、静默时段都已实现 |
| ③ 自主 | 有了连续，才谈得上自己生成问题 | **未跨** —— 巡检不发明问题；"想要"这一级不存在 |
| ④ 多主体 | 长期 | 未开始 |

**最重要的那一件缺口：它还不主动。** 它是被问才醒的。它可以按时巡检，但在巡检里它不决定去查什么。它有一个内生议程机制，而那个机制的驱动源是**规则**（某条记录陈旧了、某笔账还开着），不是想要什么。

怎么算做完：在某一天没人说话，而账本仍在增长，且增长的不是巡检的例行记录。

## 还缺什么

从账本里读出来的，不是愿望清单。

| 缺口 | 状态 |
| --- | --- |
| 检索面 | 在改善，仍有盲区 —— 单词查询打不过打分器阈值，所以归一化（`score = inter / eff`，`eff` 属于结论自身）才是真瓶颈 |
| 源码注释里的裸编号 | 还不是链接 |
| 论文标着"待作者终审" | 需要作者本人，仓库自己做不到 |
| `tools/pre-commit` 不在仓库里 | 刻意如此 —— `.git/hooks` 是本地的，克隆后装一次 |
| 一轮完整循环的实录 | 上面那个场景是散文；真实跑一轮的记录会是更好的证据 |

## 已知问题：经网关用 Gemini 会 400

不是本插件的问题。三条事实，可在 `test/tool-schema.test.mjs` 复现：

| 做法 | 结果 |
| --- | --- |
| 本插件现在输出的（`required: true` 写在属性内部） | 被 `defineTool` 接受，且是标准 JSON Schema |
| 直接喂标准 JSON Schema | 被拒：`unsupported JSON schema: parameters.type must be a value schema object` |
| 扁平属性字典 | 被接受，但 `required` 被静默丢掉 |

报错里那个 `required: true` 位于属性*内部*，而 `defineTool` 从不这样输出 —— 所以送到网关的东西不是本插件的输出。**而那个看起来顺理成章的"改成标准 JSON Schema"会让插件加载失败。** 不要那么改。

绕开：用 DeepSeek 或其他 OpenAI 兼容模型。如果你的插件曾跑在 Gemini 上，把 host 版本与网关类型写进 [issue #1](https://github.com/NBagent-dev/metaflywheel/issues/1)，这件就从"指向"变成"定位"。

## 语言与数据

界面自带中文与英文。切语言不用重启宿主：

```bash
echo en > .mpm/locale          # 或：MPM_LOCALE=en
```

优先级是刻意的：显式参数 > 环境变量 > `.mpm/locale` > 进程内覆盖 > 默认。环境变量压过文件，因为它意味着*运维决定了*。

数据层是另一个问题，而答案很简单：**账本用它使用者说的语言写，并且永不翻译。** 它是"发生过什么"的记录，不是界面文字；翻译它等于毁掉那个遗物。

| 层 | 策略 |
| --- | --- |
| 引擎文案 —— 快照行、工具描述、报告 | 经 `t(key)` / `TOOL_EN` 本地化 |
| 结论、叙述、`myAction` | 一次写成使用者说的语言，永不翻译 |
| 判据 | 只断言结构（键、计数、布尔），永不断言某种语言的子串 |

缺译文时回落到源语言，同时让 CI **变红**。未知语言回落到源语言，**不是英语**。

要给文档加一种语言：把 `README.md` 复制成 `README.<tag>.md`、**整篇**翻译、加进每一个语言栏、保持小节数一致 —— 有一条判据在查这件事，它就是这样发现"某一节只加进了一种语言"。不做自动翻译：机器输出看起来完整却没人核对，而"没核对过的话不发版"是本仓库的全部要点。

## 如何贡献

这里要的不是代码风格，是**你有没有留下一条可核对的记录**。任何改动应能回答三个问题：

1. **它解决了一个什么具体问题？** 不是"改进了架构"，是"判据 X 在条件 Y 下误报"。
2. **你怎么知道它解决了？** 要么一条新判据因为它变红，要么某个量测器的数字变好。
3. **它可能错在哪？** 在评审之前，你自己在数据上验一遍。

下面这些规则都从那条门槛长出来，而且每一条在本仓库都先被违反过：

- 判据必须能在**旧代码上变红**；一个不可能失败的检查比没有更糟
- **负控**（故意让判据失败一次，看它会不会红）—— 如果沉默也能通过，那"通过"什么也没证明
- 只报数字的量测器不许进测试套件；混在一起会让"全绿"失去意义
- **断言的范围不许大于夹具能控制的范围**
- 缓存键必须覆盖所有影响输出的输入 —— 这在实机上真错过三次
- 退休不是删除：过时的结论退出检索，但仍可按编号查到
- 用了摘要，就要把组成部分打印出来 —— 否则摘要会掩盖它所摘要的东西
- 量一种新能力之前，**先证明尺子是对的**（否则"没变化"和"没测量"长得一样）

提交之前：

```bash
node --test                                  # 必须全绿
cp tools/pre-commit .git/hooks/pre-commit    # 装一次，之后每次提交都查
```

写**为什么**，不是改了什么。如果改动来自一条已记录的决定，带上它的编号：`fix: 判据 ⑦ 把日期读错了 (P571)`。

你不需要先读论文；你不需要看懂内部编号 —— `P019-M14` 只是记账，**如果你只想知道这个项目在干什么，你永远不需要读任何一个编号**；你也不需要认同这个项目的目标。一个让测试更快的改动，在哪种立场下都值钱。

## 参考

```
engine/            引擎本体（宿主插件，不是独立进程）
  modules/         一个模块一个文件
test/              四类文件，见下
docs/              论文（草稿）· 实现说明 · 编号索引
tools/             提交前闸门、探针、量测器
install/           挂载与部署
view/              可选可视化
```

| `test/` 里的类型 | 命名 | 在 `node --test` 里 | 用途 |
| --- | --- | --- | --- |
| 判据 | `*.test.mjs` | 是 | 不满足就失败 |
| 量测器 | `audit-*.mjs` | 否 | 只打印数字，不断言 |
| 生成器 | `gen-ledger-doc.mjs` | 否 | 重新生成 `docs/ledger.md` |
| 一次性脚本 | `check-*` `read-*` `run-*` | 否 | 因为当时有用，所以留着 |

`docs/ledger.md` 由账本生成 —— 不要手改。它是这里最大的文本文件，所以每次账本变动都是一个大 diff；那是已知代价。

有两条判据是环境感知的，会自己跳过并打印原因：源码与运行副本比对，以及 `defineTool` 契约检查。那个"跳过"才是"干净克隆也能跑"为真的原因。

论文 [docs/theory.md](docs/theory.md) 标着"待作者终审"。它不是已发表文献，不应被当作外部权威引用。
